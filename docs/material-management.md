# 素材管理：已实现的方案与使用预期

日期：2026-10-14。适用于电脑端、本机家庭使用；默认 A4 竖版不变。

## 现在怎么存

| 数据 | 保存位置 | 新增空间与清理规则 |
| --- | --- | --- |
| 目录引用的照片、视频 | 用户原来的目录或挂载硬盘 | 仅建索引，不复制原件，不修改原目录 |
| 百度网盘素材 | 网盘；本机登记账号范围和文件 ID | 可用缩略图按需缓存，原片在详情中明确准备 |
| 正文、布局、素材关联、设置、历史 | 本地 SQLite 资料库 | 持久保存，清理浏览器不会删除 |
| 封面、章节采用的照片及视频关键帧、录音 | 资料库 `objects/` | 保留，不参加普通缓存清理；原目录离线仍可读游记 |
| 小缩略图、网盘临时原片 | 资料库 `objects/`，数据库标为 cache | 默认完成缓存预算 5 GiB，可调整，按最近使用顺序回收 |
| 普通选文件、拖入文件、完整迁移旧项目 | 资料库的原件副本 | 用户选择后复制，按 SHA-256 与其他副本去重 |

默认资料库为当前用户主目录下的 `行迹资料库`，包括 `library.sqlite`、SQLite 的 WAL/SHM 文件、`objects/`、`temporary/` 和 `exports/`。分类保存在数据库中，物理文件按 SHA-256 共用，不另外为每本游记保存一份相同原片。游记分别保存图注、裁切、顺序与章节关系。

如需另一块硬盘，可在启动前设置 `TRAVEL_DATA_DIR`。已有资料库迁移时，先关闭服务，再完整移动目录，然后使用新路径启动；不要在运行中只复制 `library.sqlite`。

## 推荐操作

1. 在游记素材页点击 **引用素材目录**。扫描只读取目录、文件状态和少量照片元数据，不逐个读取整个视频。单本支持最多 2 万个素材，网格每页展示 60 个。
2. 预览按需生成，照片处理并发限制为 2。照片的普通缩略图最长边 640 像素，打印图最长边 3200 像素；视频帧最长边 2400 像素。PDF 按实际保留图像像素检查清晰度，不用原件尺寸冒充输出质量。
3. 选片、编辑并建立章节。封面与章节配图自动准备保留画面；导出 PDF 或备份时再次核验配图是否可用，缺失时明确提示。
4. 在 **素材与存储** 查看副本、保留画面、缓存和索引对应原件的容量；可设缓存预算、清理普通缓存或清理已解除关联的副本。

普通浏览器的文件选择与拖放不会提供可靠的绝对路径，所以该入口明确标为保存副本。大量素材优先使用目录引用。Windows/macOS/Linux 的系统目录选择器各自调用本机接口；没有图形选择器时可粘贴路径。原文件仍受操作系统权限限制。

百度直连先确认账号，导入不会把整段视频下载进浏览器。准备原片时，本地服务直接流式写入临时文件，再提供 HTTP Range 播放和截帧；单个原片超过缓存预算会提示调整预算，或先用百度桌面客户端下载到电脑后引用。正常关闭详情会释放临时原件，异常关闭后由缓存机制回收；打开的详情有短期播放会话，普通清理会保留正在使用的原片。

网盘文件的大小、MD5（提供时）与修改时间组成版本信息；变化后旧游记采用的画面保留，重新登记才能使用最新原片。Token、Client Secret 与模型密钥均不进入资料库或备份；本地服务的网盘会话只驻留内存并有有效期。

## 空间预期

采用目录引用后，新增占用主要为 **索引与文字 + 已采用画面与录音 + 普通缓存**，而不是素材总容量。比如原目录 100 GB，游记采用 300 个画面，假设每张打印 JPEG 平均 1 MB，那么保留画面约 300 MB，另加录音、索引和实际使用的缓存；不会再因为导入而复制那 100 GB。这是计算示例，真实 JPEG 大小与照片内容有关。

5 GiB 约束的是已完成的普通缓存。下载过程的临时文件、保留内容、数据库、显式原件副本和导出包另占空间；大下载前会检查剩余空间，传输中断会删除该次临时文件。关闭服务时被系统强制终止的临时文件仍可能残留，应在确认没有任务后检查 `temporary/`。被正在使用的素材占满预算时，新下载会失败并保留已有内容。

引用导入与视频播放取消了旧的 500 MB 原片缓冲上限；不承诺任何大小的视频都可解码。照片的浏览器预览处理暂限原图 500 MB，巨大图片还受解码内存限制。HEIC、HEIF 和视频编码兼容性取决于浏览器。

## 原目录搬家与旧项目迁移

目录整体搬家：在 **素材与存储 → 目录搬家** 指向新根目录，原相对路径和素材 ID 保留。大小、修改时间或版本不符合登记记录时会报告原件变化，已采用画面仍然保留；改名或内容变更需单项核对。

旧浏览器项目：在原浏览器、原应用地址打开新版，进入 **素材与存储**。

1. **迁移文字和画面** 把项目、已有缩略图/关键帧和录音保存到资料库，暂时保留浏览器中的原件。也可主动选择连同原件完整迁移，会增加磁盘占用。
2. 登记原素材目录，使用 **关联旧副本**。按文件名、类型与大小寻找唯一候选，然后流式核对完整 SHA-256；视频不会仅凭同名或大小判定相同。也可在单个素材详情中选取候选。
3. 核验成功后原件关联改为引用。通过 **核验后清理旧浏览器数据** 释放 IndexedDB 占用；任一原件、画面或录音没有安全副本或有效核验记录时，拒绝清理旧项目。
4. 若此前完整迁移过原件，重新关联后还可清理资料库已解除关联的原件副本。历史版本保留画面与录音，不永久锁住已解除关联的原片副本。

迁移可重试，重复迁移不会覆盖资料库中后来修改的正文。旧原件完全丢失且没有可信哈希时无法证明候选相同；单项界面允许用户明确确认“按所选文件重建引用”，不会自动执行这种替换。

同一资料库可由本机不同浏览器使用。保存带版本检查，多窗口的旧数据不会悄悄覆盖新数据；冲突时可先下载文字 JSON 备份，再刷新。编辑历史最多 20 份、每分钟最多一份，可以恢复文字与布局；删除或清理的原件副本不随历史恢复。

## 备份与恢复

| 备份 | 包含什么 | 适合什么场景 |
| --- | --- | --- |
| 游记备份（推荐） | 文字、布局、所有素材信息、封面及章节采用的画面、录音 | 离线阅读、继续编辑、迁移游记，体积较小 |
| 游记与原件备份 | 上述内容 + 封面及章节采用素材的完整原件 | 换电脑后仍可重新截帧或重新生成图片 |
| 文字 JSON | 正文、布局和素材索引 | 抢救/留存文字，不保证离线有画面 |

前两项采用文件夹格式 `version:2`，逐个流式写入 `media/`、`audio/`，最后原子写入 `project.json`。不把全部视频聚合到浏览器内存，没有旧 ZIP 的 1 GB 总包上限；容量取决于磁盘、文件系统与清单限制。网盘原件备份在有效账号连接下直接流式下载到备份目录，避免再生成临时原片副本。

未采用的候选素材只记录引用，不随游记包复制整个素材库。需要保留整个原素材目录时，应使用文件系统或百度网盘另外备份该目录。

恢复先核对每个文件的大小、SHA-256 和路径范围，损坏/越界文件不生成恢复项目；新项目、章节、素材和回忆使用独立 ID。原件直接引用备份文件夹，保留图和录音写入资料库；恢复后若移动或删除备份目录，也需要更新原件引用。

仍支持恢复旧 `version:1` ZIP 和 JSON。旧 ZIP 恢复暂限 1 GiB 解压素材，JSON 清单暂限 5 MiB；新文件夹清单暂限 16 MiB，最多 5 万个文件条目。超过限制明确报错，不截去末尾条目。

这版不包含跨设备自动同步、百度网盘写回、整素材库云备份、视频转码代理、AI 相似照片筛选、人物识别或旅行地图。真实百度授权与下载权限需要用自己的账号验证，自动化使用模拟响应。

具体验证结果见 [验证记录](validation.md)，后续功能建议保留在 [同类应用调研](storage-and-feature-research.md)。
