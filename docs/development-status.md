## 接续规则

1. 先核对远程main、当前工作区及最近提交，保留现有未提交工作；不要重做已交付功能，也不要并发启动相同开发。
2. 每个新增需求或修复提交对应的正常、错误和边界用例；新增后运行 `npm run verify` 全量回归。环境需要Node 24、Chromium、FFmpeg和Poppler；可用 `CHROMIUM_PATH` 指定浏览器。
3. 测试通过后直接提交main，不强推、不覆盖其他人的提交。把实际测试结果及下一步更新到本文件。
4. 受额度或工具限制时记录阻塞与未完成事项，不把未执行的测试标为通过。定时接续只能在执行环境和额度可用时尝试，不能绕过限制。
5. 五项需求全部完成并提交后，暂停本项目接续任务，避免持续创建无需求改动。

## 验收边界

- 相似图算法给出本地候选，不保证识别所有裁剪、旋转或变焦。
- 自然语言搜索使用画面描述加文本向量；已通过可控模型HTTP集成测试，真实云端模型识别质量尚未用用户凭据验收。
- 视频由用户提供长期HTTPS观看链接；系统不自动托管视频，不能保证第三方链接永久有效。
- 实际纸质打印、不同操作系统与手机视频编码仍需真实设备样本验收。
